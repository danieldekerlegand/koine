## Codebase Patterns

- **`.chief/verify.sh` selects gates from CHANGED PATHS.** Touching `docs/**` or `specs/**`
  selects `guard-doc-integrity`, which fails on ANY dead relative link in the whole tree — not
  just yours. Latent breakage on main becomes YOUR merge blocker. Run
  `node scripts/check-doc-integrity.mjs` early, and compare against a clean HEAD checkout
  (`git archive HEAD | tar -x -C $(mktemp -d)`) to tell inherited from introduced.
- **`verify.sh` diffs against the base branch, so it reports "no changed files" until you commit.**
  Commit first, then run it.
- **Not every spec edit bumps the version.** KGP's changelog has `**Editorial** (date)` entries
  that leave version + status alone — use that form for pointer/tracking-prose corrections. It
  keeps the four status mirrors (README.md, specs/README.md, ECOSYSTEM.md §2, CLAUDE.md
  *Current state*) untouched, which is the expensive part of a bump.
- **`docs/README.md` says "a document not linked here does not exist."** A new file under `docs/`
  must be added to that index or it is dead weight.
- **When a tasklist moves to `tasks/chief/completed/`, links to it in `specs/` break.** There were
  9 such links on main for `53-multi-authority-scenario.json`.

### Design decisions worth reusing

- **No current-version column, deliberately.** `check-doc-integrity.mjs` machine-checks exactly three
  mirror files (`README.md`, `specs/README.md`, `ECOSYSTEM.md`) against the spec headers. `docs/` is
  not one of them, so a version column there would be a **fourth, unchecked mirror** — the same trap
  `CLAUDE.md`'s *Current state* prose sits in. Only *historical* versions appear (the release that
  ratified, the release that demoted); those are immutable and cannot rot. The page says this in as
  many words so the next editor does not "helpfully" add the column.
- **Program view vs status view kept separate.** `ROADMAP.md` Phase 1 is the program (tasklists,
  phases, scale) and covers **four** of six — KINP and KCS were still ratified when it was scoped and
  have no row. Rather than widen Phase 1, the new page is the six-row status view and Phase 1 now
  says which two it omits and why.
- **The `53` wrinkle is explained, not repeated.** Three specs cite
  `chief/53-multi-authority-scenario` as a live gate while it sits in `completed/`. Not a bookkeeping
  error: `53`'s scope was to **write and run** the break test and it did. What the specs wait on is
  the **fold**, which is `85`. The page says the three status notes should be repointed when that
  fold lands.
