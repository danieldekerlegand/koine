## Codebase Patterns

- **`.chief/verify.sh` selects gates from CHANGED PATHS.** Touching `docs/**` or `specs/**`
  selects `guard-doc-integrity`, which fails on ANY dead relative link in the whole tree — not
  just yours. Latent breakage on main becomes YOUR merge blocker. Run
  `node scripts/check-doc-integrity.mjs` early, and compare against a clean HEAD checkout
  (`git archive HEAD | tar -x -C $(mktemp -d)`) to tell inherited from introduced.
- **`verify.sh` diffs against the base branch, so it reports "no changed files" until you commit.**
  Commit first, then run it.
- **Not every spec edit bumps the version.** KGP's changelog has `**Editorial** (date)` entries
  that leave version + status alone — use that form for pointer/tracking-prose corrections. It
  keeps the four status mirrors (README.md, specs/README.md, ECOSYSTEM.md §2, CLAUDE.md
  *Current state*) untouched, which is the expensive part of a bump.
- **`docs/README.md` says "a document not linked here does not exist."** A new file under `docs/`
  must be added to that index or it is dead weight.
- **When a tasklist moves to `tasks/chief/completed/`, links to it in `specs/` break.** There were
  9 such links on main for `53-multi-authority-scenario.json`.

**Learnings for future iterations**

- **Read the commits, not the tasklist.** `git log --oneline <base>..<head>` and
  `git show --stat <merge>` settled this in two commands. A retire step can blanket-flip stories
  it never ran; the tell is `notes: null` on a `passes: true` story, and chief's own
  UNVERIFIED rule exists precisely because that happens.
- **Check the retire commit's diff**, not just the final tasklist state — that is where the
  unearned flips live.
- Cross-repo verification means reading the other repo's working tree at HEAD as well as at the
  cited sha, so "nothing was added since" is a checked fact rather than an assumption.
