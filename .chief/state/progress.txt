## Codebase Patterns

- **Two kinds of scenario.** A full `e2e-*.md` pass walks a whole story across participants and
  emits a delta series; a **focused pressure leg** (`kmi-otio-roundtrip.md`, now
  `kft-resume-checkpoint.md`) attacks ONE open question of ONE spec and says explicitly which
  questions it does *not* force. Use the focused shape when a tasklist names a single §-numbered
  open question. Copy `kmi-otio-roundtrip.md`'s skeleton: Purpose → Setup (roles + KINP §3.4
  placeholders) → numbered Steps each marked ✅/🟡/🔴 → Findings table → an explicit
  "only §N is forced" section listing every sibling question left alone.
- **Prove the leg is not rigged.** Both finetune-adjacent precedents open with a step that *holds*
  and close with a "what held" section. A leg that only breaks reads as manufactured; a leg that
  confirms the half of the question that already works, then breaks the other half, is what earns
  the fold.
- **Adding a scenario means editing `scenarios/README.md`.** Add a table row. The counts in that
  file ("eight documents", "`planned` eight times") refer to the **KCS-encoding-gated** rows only —
  a focused leg carries `⬜ **focused pressure leg** — follow-up to <parent>` in the last column
  and moves none of those counts.
- **`.chief/verify.sh` path-selects its guards from the CHANGED files.** Touch any `.md` and
  `guard-doc-integrity` + `guard-doc-links` become merge blockers for your branch — even if they
  were already red for reasons predating it. Run `bash .chief/verify.sh` after committing (it
  diffs committed state, so it reports "no changed files" on an uncommitted tree). To tell a
  pre-existing failure from one you caused, stash with a unique tag and re-run on baseline.
- **Quote the spec verbatim when asserting a break.** Every finding in these scenarios cites the
  clause it breaks by section number and quoted phrase. `sed -n` the clause before writing the
  claim — a paraphrased gap is not a delta.

### Learnings for future iterations

- **A pre-existing red gate became this branch's merge blocker.** `tasks/chief/53-multi-authority-scenario.json`
  had been retired into `tasks/chief/completed/`, leaving 9 dangling links across KINP/KCB/KMI.
  `check-doc-integrity` was already failing on `main`, but `verify.sh` only *selects* that guard when
  a doc changes — so the moment this branch touched `scenarios/README.md` it inherited the failure.
  Fixed as a link-target-only repoint in its own commit. **Expect this class of breakage whenever a
  tasklist is retired**: any spec citing it by `../tasks/chief/<name>.json` goes dangling.
- **FT-S is the finding US-2 should lead with.** FT-R is the missing field, but FT-S is the one with
  teeth: §5.4's inheritance is scoped to "the finetuned model entity and every weight/export asset
  **it generates**", and §5.2 mints the model at *completion* — so nothing in KFT today assigns an
  egress class or license to a mid-run checkpoint, even though §6 publishes its id on a `subscribe`
  stream and tells consumers to `fetch` it lazily. That hole exists **independently of resume** and
  a fold that only adds a `resume` field would leave it open.
- **The fold must stay additive and must touch §3.3.2.** §3.3.1 forbids leaving any §3 field
  unclassified, so a new top-level field needs a row in §3.3.2's matrix with a disposition. Its own
  gating test ("changing it changes what the run is") is met, so the disposition is REFUSE-if-pinned
  unless the target expresses it.
- **`schemas/finetune-job.schema.json` is `additionalProperties: false` at the top level and inside
  `dataset`.** There is no vendor escape hatch by design — so any US-2 job-shape change is a real
  schema edit, and `schemas/fixtures/finetune-job.json` must stay valid.
- **The research map was not provided for this tasklist**; everything above was derived by reading
  `specs/fine-tuning.md` (§2, §3, §3.1–§3.3, §4.2, §5.1–§5.4, §6, §7, §8.1, §11), the three existing
  finetune scenarios, `registry/relations.tsv`, and the schema. Future iterations can start from
  this note instead.

**The shape of the fold.** The leg's five findings are five faces of one question, so they folded as
one clause set rather than five patches:
- **§3.4 (new, NORMATIVE)** — the optional top-level `resume` `{checkpoint, of_job, at_step}`, with a
  table separating **warm start** (`base_model`, confirmed as needing no new surface) from
  **resumption** (a mid-run checkpoint). Four rules: pinned input (enters §5.2 `used[]`, so FT-C's
  anchor keeps determining the run) · **the only slot** (a ref in the permissive `hyperparams` is
  refused `invalid`, not executed) · never corpus (gates without being priced) · a new activity.
- **§4.2 / §4.3** — the checkpoint joins the effective-egress aggregate and the union license/tier.
- **§5.4** — a checkpoint inherits **at publication**, not at completion. This was FT-S's real teeth
  and it is a hole that exists **with or without resume**, on the §6 `subscribe` stream.
- **§5.2** — a continuation leg is a NEW activity linked by the new core relation **`continues`**.
- **§6** — `job+step` idempotency stays sound (distinct legs ⇒ distinct `job` ids), `step` counts from
  the root leg so legs overlap deliberately, plus a NORMATIVE curve-**join rule** and an optional
  non-authoritative `attempt` ordinal.
- **§7** — estimate the **remainder**, verify `at_step` against the prior leg's provenance, check
  against the ceiling **net of cumulative `spent_units` across the chain**.
- **§3.3.1/§3.3.2** — gating set gains `resume.checkpoint`; two matrix rows and a **fifth** normative
  consequence (converts to a local *path*, so id/`of_job`/`at_step` go out of band; a target with no
  resume surface is refused rather than handed a cold run).

### Learnings for future iterations

- **`schemas/fixtures/` allows exactly ONE fixture per schema, by filename.** `check-schemas.mjs`
  derives `<fixture>.schema.json` from each fixture's name and errors if it does not exist, so
  `finetune-job-resume.json` is rejected outright — there is no way to ship a second, contrasting
  fixture for one schema. A new optional field is therefore exercised by **editing the golden
  fixture** (what 0.5.0 did for `descriptor[]` / `base_model_descriptor[]`), and the additivity claim
  is carried by the schema's `required` list plus prose, never by a second artifact. Don't spend a
  round discovering this.
- **A version bump touches FOUR mirrors, and only three are checked.** `README.md`,
  `specs/README.md` (**two** places — the table *and* the candidate-count sentence around line 195,
  which names every candidate spec by version) and `ECOSYSTEM.md` §2 are diffed by
  `check-doc-integrity`; `CLAUDE.md`'s *Current state* prose is not. The prose sentence in
  `specs/README.md` is inside the checked file but is **not** part of the table diff — a stale
  version there passes CI just like CLAUDE.md's.
- **Match the changelog's own register.** Each KFT entry is a titled bullet list where every
  sub-bullet names a section and states what moved *and why it is not a redesign*. Two things the
  precedent always does and that reviewers look for: say explicitly whether §4's **admission
  behaviour** moved (0.5.0 said byte-unchanged; 0.6.0 says it *does* move — but only for a job
  carrying `resume`, never for a cold one), and restate the outstanding gate rather than replacing it.
- **A fold that adds normative text adds a gate.** KCB 0.4.6 and KMI 0.3.4 both did this ("a third
  candidate count", "a second candidate count"). 0.6.0 follows: the leg itself becomes the second
  gate, since it was written against 0.5.0 and each finding is now answered — Steps 2–6 must walk
  clean where they broke, Steps 1 and 7 must stay held.
- **A new relation is cheap and additive; editing one is forbidden.** `continues` slotted into
  `registry/relations.tsv` beside `retrains`/`supersedes` with no guard friction (`check-registry`
  went 27 → 28 names). What the immutability rule forbids is changing a **published signature** — so
  when a lifecycle question needs a verb the registry lacks, mint a new name rather than widening an
  existing description.
