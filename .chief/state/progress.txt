## Codebase Patterns

- **Scenario documents follow a fixed shape.** Title + *Purpose* (naming the exact spec versions
  under test and quoting the invariant) → *The story* → *Setup* table in KINP §3.4 placeholder
  namespaces → numbered **Steps** each tagged ✅ *held* / 🔴 *broke* / 🟡 *noted* → *Assertions — as
  KCS steps* (a table mapping each assertion to a KCS §5 predicate, with `— **none**` where the
  format cannot express it) → *Findings* table (`# | Severity | Gap | Delta | Spec`) → a
  *Not deltas — what this pass tried to break and could not* paragraph → *Verdict* →
  *Re-ratification / Resolution*. `scenarios/e2e-live-schema-mutation.md` is the best model.
- **Findings must be grounded in quoted clause text.** Read the actual §-text before writing a
  break; every finding here cites the sentence it contradicts. Recording what *held* under a named
  attack is as load-bearing as the breaks.
- **Adding a scenario means four doc edits, not one.** The file, the row in `scenarios/README.md`'s
  table (incl. the *KCS encoding* column), the prose counts in that README ("These N documents",
  "`planned` N times", "encodes the N documents", "the attempt at the N above"), and the two count
  sentences + the F4 milestone row in `ROADMAP.md`. None of those counts is machine-checked.
- **Verify with the real gate, not just the guard.** `git diff --name-only <base>...HEAD |
  .chief/verify.sh --plan` shows which gates the diff selects; `.chief/verify.sh --run <files>`
  runs them. A prose branch selects guard-doc-integrity + guard-doc-links + verify-selftest.

## US-1 — A two-authority pressure scenario hunting the shared-pattern break (2026-08-24)

**What I did.** Wrote `scenarios/e2e-multi-authority.md` (522 lines), the ADR-0012 federation
break-test that KINP 0.3.0 §11.1, KCB 0.4.6 §3.1 and KMI 0.3.4 §7.1 each name as their candidate

`e2e-worlds-to-fabric.md` deployment (`refkb` / `orchestrator` / `analyzer` / `worldsim` /
`mediastore`), domain B is an archive (`archivekb` / `coordinator` / `assetstore` — three new
placeholder registrations in KINP §3.4's illustrative style, since the existing set has exactly one
of each authority-ish role). Ten steps, adversarial throughout.

**Files changed.**
- `scenarios/e2e-multi-authority.md` (new)
- `scenarios/README.md` — table row + the four prose counts
- `ROADMAP.md` — two count sentences + the Phase F4 encoding milestone (`kcs:multi-authority`)

**Findings the pass produced.** MA-1…MA-11; six blocking.
- MA-1 (H) query-time `same_as` closure (§4.1) unions two authorities' links, governed by its
  weakest link — a merged identity no authority asserted and no review gate saw; re-running
  `e2e-worlds-to-fabric.md`'s Q2 now leaks fiction.
- MA-2 (H) §4.5's relation-choice rule needs the candidate's world + inherit-as-identity mode; both
  are published in the *other* domain, no KCB verb returns them, and §4.5 has no branch for a
  **missing operand** (its third branch is about confidence) → the firewall is absent on the second
  authority.
- MA-3 (H) §6 re-expresses claims against "**the** canonical entity" — singular; two holders means
  two claim ids for one fact, and nominating a target reinstates ADR-0012's rejected option (a).
- MA-4 (H) the world is *inside* the claim hash (§6) and §5 makes the default real world the
  authority's own, so two consensus realities → two hashes even for a shared `wikidata:` anchor; §4.2
  ranges over entities, so nothing can assert the two worlds are one. Also strands KGP §7's
  `world = consensus-reality` filter.
- MA-5 (H) KMI §7.1(e)'s egress gate has **no operand** — the §2 envelope carries no `license` /
  `egress`, KGP §7's classes are record properties, and §7.1(d) forbids synthesizing the envelope
  that would carry them. Both horns conformant, both wrong.
- MA-6 (H) discovery federates, authorization does not: §5 grants come from one host; §3.1 returns
  addresses nobody can authorize a call to. KMI §7.1(b)(e) inherits it for `fetch:asset`.
- MA-7 (M-H) federation reintroduces one unfederated authority — §3.4's prefix registry.
- MA-8 (M) three of §3.1's six clauses have no carrier in §3's `find` response.
- MA-9 (M) peering has no horizon and no de-dup key. MA-10 (M) no durability floor: *pending fetch*
  becomes unfalsifiable. MA-11 (cleanup) KCS §5 has no authority-boundary vocabulary (V-8's class).

**What held under attack** (the three acceptance-criteria invariants, two of three):
offline-first minting with both authorities gone — including the world-stamp back door — and asset
id byte-stability across stores (re-minting forbidden, corrupted bytes rejected by the mandatory
verify, C2PA/OMC projections gained no spurious derivation). The third invariant, *no query-time
merge produces a false cross-authority identity*, **failed** — MA-1.

**Verification.** `node scripts/check-doc-integrity.mjs` → OK, 43 markdown files, 705 relative links
checked, all 3 status tables match their headers. `.chief/verify.sh --run` over the changed set →

**Learnings for future iterations.**
- The research value is in *reading the clause before claiming the break*. Several findings only
  exist because §2's envelope, §5's world default and §6's hash inputs were read literally — e.g.
  the world being inside the claim hash is what makes MA-4 independent of MA-3.
- The verdict shape matters: this pass is the **inverse** of `e2e-live-schema-mutation.md` (there,
  one spec's model held and its perimeter leaked; here, three edits are each locally sound and every
  break is at a seam none of them owns). Say which shape a pass has — it is what tells the owner
  whether to fold or to reconsider.
- US-2 must add the *Re-ratification — what this pass gates* section (a per-spec table + *what a

- The research map in the PRD was accurate; no correction needed.
