## Codebase Patterns

- **Run the guards from the repo root, and use the runner's own seam.** `node scripts/check-doc-integrity.mjs`
  (wall: every relative link + all 3 status tables) and `node scripts/check-doc-links.mjs --ratchet --base main`
  (ratchet). To gate exactly what you changed *before committing*, use
  `bash .chief/verify.sh --run <paths...>` — a bare `.chief/verify.sh` reads the branch diff and
  reports "no changed files" for uncommitted work.
- **Anchor slugs are the guard's, not GitHub's.** `scripts/check-doc-integrity.mjs` `slugify()`:
  strip `` ` `` `*` `_`, unwrap `[text](url)` to `text`, lowercase, drop `[^\w\s-]` (so `/`, `—`,
  `,` vanish), trim, `\s+` → `-`. An em dash therefore collapses into a double space → single
  hyphen. Write the anchor by applying those five steps, not by guessing.
- **One home per fact.** Where a table already exists (the ADR table in `decisions/README.md`, the
  three spec status tables), link it — do not restate it. Restating is how the four version/status
  mirrors got expensive.

### Learnings for future iterations

- **The drift is almost always a RESTATED fact, not a wrong one.** Five of the six were a copy of
  something whose home is elsewhere (a count the status tables hold, the spec's own §2 example, a
  directory listing). C-3 and C-4 were *correct on the day they were written*. So the fix that
  lasts is to **delete the copy and point at the home** — four of six fixes did that. Refreshing a
  restatement just re-arms it.
- **`Updated:` in a banner is not a shelf life.** C-1 even said *"That is a dated reading"* and
  still misled, because a date does not stop a number being read as current. Prefer holding no
  count to holding a dated one.
- **Where to look for content drift in this repo, in order of yield:** (1) tables that count things
  in a directory — `implementability-audit.md` §1 is one and it re-counts in 30 seconds; (2) any
  prose stating how many specs are `ratified` (CLAUDE.md already warns about this class); (3) worked
  examples in `docs/guides/` and `docs/explanation/` against the spec section they illustrate — a
  spec that fixes its own example does not propagate; (4) `README.md` / `CLAUDE.md` lists of
  directory contents.
- **Left for US-3, found here:** `ROADMAP.md`'s Phase 0 paragraph reads *"That count is **0 of 6**"*
  and has been wrong since KGP was ratified on 2026-08-28. **Deliberately not fixed** — the tasklist
  description puts roadmaps out of scope in as many words. Reported in the register instead. If a
  future story is allowed to touch it, that is the one-line fix.
- **`docs/reference/doc-drift-corrections.md` is where US-3's AC2 and AC3 belong.** It already has
  a *Scope, and what this sweep did not touch* section (ROADMAP, upstream-standards, the governance
  map) and a *What this sweep cannot claim* section. US-3 should EXTEND those rather than start a
  second document — and must flip `docs/README.md`'s `archive/` row from "created on first use" the
  moment it archives anything.
- **Nothing was archivable in this story.** No document was found superseded — every one is either
  current or an explicitly dated record of a pass. `docs/archive/` therefore still does not exist
  going into US-3, and that is a finding, not an omission.
