## Codebase Patterns
- **Guards to run after any doc/spec edit:** `node scripts/check-doc-integrity.mjs` (relative links +
  anchors + the 3 status-table mirrors), `node scripts/check-tasklist-categories.mjs`, and the merge
  gate itself: `.chief/verify.sh --run <changed files…>` (it selects gates from paths; `--plan` reads
  STDIN). The *Current state* prose in CLAUDE.md is a FOURTH mirror that is **not** checked — update
  it by hand when a spec version moves.
- **A new doc must be linked from `docs/README.md`** — the repo's stated rule is "a document not
  linked here does not exist". check-doc-integrity does not enforce it; the map is the contract.
- **Version discipline in this repo is deliberate and quotable.** KCB lands additive normative text
  as a PATCH (0.4.6 added six §3.1 clauses; 0.4.7 added §4.2) because **0.5.0 is reserved** for
  §2.2's standalone-manifest removal; KMI's 0.4.0 is likewise spent on the EDL removal. Check what
  the next minor is already spoken for BEFORE choosing a bump.
- **Relations are immutable:** never edit a signature in `registry/relations.tsv` — mint a new name
  (precedent: KFT 0.6.0's `continues`).
- **KINP owns identifiers/worlds/resolution semantics**; other specs reference, never redefine. That
  rule decides where a cross-spec fold lands, and it is how a fold avoids adding a gate to a spec
  that is close to promotion (KGP).
