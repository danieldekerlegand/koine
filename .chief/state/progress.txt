## Codebase Patterns

- **A "pressure leg" is the unit of work here.** koine is a contracts repo: a spec clause only moves
  after a `scenarios/` document breaks it. The newest and tightest model is
  `scenarios/kft-resume-checkpoint.md` — read it before writing a new leg. Shape:
  Purpose (name the spec + version + the exact open question, quoted) → Setup (roles table +
  abridged manifest + the numbers) → numbered Steps each tagged ✅ held / 🔴🟡 broke → **What held**
  (so the fold stays narrow) → **Findings** table (severity · gap · forced question · spec) →
  **Only §X is forced** (explicitly *not* reopening other legs' deltas) → **Re-ratification — what
  this pass gates** (per-spec table + a dated `> **Resolution:**` blockquote).
- **Delta prefixes are per-leg and must be fresh.** F–L (media-transform), V-1…V-8 (live-schema-
  mutation), MA-1…MA-11 (multi-authority), FT-A…V (finetune legs), BP-1…BP-6 (this one). Grep the
  scenarios dir before picking one.
- **Every leg must add a row to `scenarios/README.md`'s table** *and* a paragraph to the narrative
  below it. `check-doc-integrity.mjs` will not catch a missing row — it only checks links and the
  three spec status tables.
- **Verify prose changes with the real gate, not just the script:**
  `bash .chief/verify.sh --run <changed files…>` — a bare `.chief/verify.sh` reports
  "no changed files" under an agent shell (it reads stdin for the file list). For `scenarios/*.md`
  it selects `guard-doc-integrity` + `guard-doc-links`.
- **Roles, never products** (CLAUDE.md), and the KINP §3.4 placeholder namespaces are fixed:
  `worldsim` (world producer) · `analyzer` (knowledge producer/consumer) · `refkb` (identity
  authority) · `mediastore` (media producer / CAS) · `orchestrator` (control-plane host) ·
  `provider:org:…` (capability providers).

**What the leg found (this is US-2's input — read the Findings table, not just this):**
- **BP-5, blocking.** §8.1 parks flow control on "the host's cost advisor", but §3 / ADR-0001 keep
  the host **off the stream path** (returns addresses; no traffic flows through it), its four
  instruments (grant, revocation, ranking, the optional facade) all fail to reach a running
  subscription, and under §3.1 federation no single host has jurisdiction over both ends. **The
  assignment is void, not deferred** — so the question cannot be discharged downstream by anyone.
- **BP-3, blocking.** Disconnect is the only working lever; `subscribe` has no resumption operand,
  KGP delta `basis` chains break across the gap, KCB publishes no range-pull verb, and a missed
  **retraction** leaves a claim asserted forever. §4's idempotency argument covers *redelivery*,
  not *non-delivery* — content-addressing makes a duplicate a no-op and a gap invisible.
- **BP-2.** `cost` is on `params.capabilities[]`; a subscription scopes to a **world**, which has no
  manifest object to price, and §5 evaluates the ceiling *"at invoke"* — a stream has no second
  invoke, so `budget_units` never decrements. Extending it does not help: enforcement *"fails at the
  gate"*, so **a ceiling is a cliff and backpressure is a brake.**
- **BP-1** (no volume/rate field on any port ⇒ firehose and trickle are identical to discovery),
  **BP-4** (delta L's lazy `fetch` amplifies onto a third participant's CAS), **BP-6** (cleanup,
  evidence for KCS open question 1 — a stalled transport window is unassertable).

**Learnings for future iterations**

1. **The PRD's section numbers are stale — trust the spec header, not the tasklist.** The PRD
   description says "KCB §7 open question 3 (~line 256)" and US-2's criteria say "§7.3 / subscribe
   clause". Both are wrong against KCB 0.4.6: **§7.3 is Deprecation**, and the backpressure question
   is **§8.1** (renumbered twice — ADR-0009 took the old q2 into §7, ADR-0012 took the old q1 into
   §3.1). US-2 should fold into a **new normative section** and update §8, *not* edit §7.3. The
   `touches`/AC intent is clearly right; only the numbering drifted.
2. **US-2's version bump needs a decision, and the leg records both readings.** All six deltas are
   additive. KCB's own precedent (§3.1 landed as **0.4.6, a patch**, on "additive + 0.5.0 is already
   spent on §2.2's removal") points at **0.4.7**. The alternative is folding into the V-1…V-8 minor
   at **0.5.0**. The leg's *Re-ratification* section states both and leaves the choice to the fold.
3. **Step 8's convergence note is the most useful thing for US-2.** V-7 (from
   `e2e-live-schema-mutation.md`) already needs an **in-band control frame on the subscription
   stream** — the push channel §7's preamble concedes is missing. BP-5 needs a frame in that same
   direction and BP-3 needs one in the other. **These two folds want one channel, not two.** A fold
   that mints a second, parallel signalling mechanism is the wrong answer.
4. **Status is already Candidate and stays there.** US-2's AC says "Status set to candidate" — it is
   candidate now, on three counts; this leg makes a **fourth**. The fold must *restate* the existing
   three (media-transform extension re-run, §7.5 live-schema-mutation re-run, multi-authority for
   §3.1) and move none of them, then add the re-run of this leg. That restate-and-do-not-move
   discipline is house style — see how KCB 0.4.6 and KFT 0.6.0 word it.
5. **The status-note block at the top of a spec is where a fold's rationale goes**, and it is long
   and cumulative by design. CLAUDE.md's *Current state* prose is a **fourth mirror that CI does not
   check** — a stale version there passes green. US-2 must update it by hand along with the three
   checked tables.

**What §4.2 says** (so a later fold does not re-derive it): (a) optional port `volume` envelope
`{unit, rate, payload_bytes, references, resume_horizon}`, **outside** the `schema_id` digest exactly
as `cost` is, absent reads *unknown* never *low*, §3 ranking untouched; (b) optional `subscribe`
`max_rate`/`max_in_flight`/`window`/`on_overflow` under the normative rule that the contract governs
**lossless vs lossy**, not *how fast* — and **a retraction is never shed**; (c) optional
content-addressed `resume.after` operand (**not** a sixth verb) a producer MUST answer resumed /
`gap-unavailable` / `resume-unsupported`, **never with silence**, plus never-silently-merge-past-an-
unseen-`basis`; (d) **one** in-band control channel, both directions, and **V-7's fold MUST ride it**;
(e) `volume.cost` is the operand §5's "at invoke" ceiling never had + an exhausted ceiling MUST NOT be
the *first* signal; (f) the fan-out is the **subscriber's** traffic and a CAS refusal lands on delta
L's existing pending-fetch tolerance; (g) shape, never QoS.

**Learnings for future iterations**

1. **Iteration 1's learning 1 was right and saved the story.** The PRD's "§7.3" is stale — §7.3 is
   Deprecation. The fold went to a **new §4.2**, under the verb it constrains. When a PRD names a
   section number, verify it against the spec header before editing; koine renumbers on every fold.
2. **Version classification is a judgement recorded in prose, not a rule.** §7 governs *capability*
   versions, not the *spec's* own. KCB's two precedents disagree on the surface — 0.4.0 added optional
   manifest fields as a **minor**, 0.4.6 added a normative section as a **patch** — but the operative
   criterion 0.4.6 states is *additive + prior-conformant-stays-conformant + 0.5.0 is spoken for*.
   0.4.7 meets all three, so it is a patch and the changelog says so explicitly rather than glossing it.
   **0.5.0 is still reserved** for §2.2's removal + the V-1…V-8 and MA-6/8/9 folds.
3. **Check `schemas/` before concluding "no twin".** `participant-self-description.schema.json`
   *looks* like it might model the KCB manifest — it does not: it is pointers-only, and its
   `capability` block says the payload is "deliberately NOT restated here" with
   `additionalProperties:false` to stop it creeping in. So an added KCB manifest field needs **no**
   schema change. CLAUDE.md's `schemas/` bullet does not list that file — a small doc gap, not a defect.
4. **The extension URI does not move for an added optional field** (§2, stated as the anti-pattern
   `compose-v2`-at-the-document-level). `…/manifest/0.3` is correct at 0.4.7. Do not bump it.
5. **`resolved in place` is now the house pattern for open questions** — KFT §11.3, KMI §9 q3, and
   now KCB §8. Strike the text, keep the entry and its number, say what decided it and (here) that
   its second clause was *wrong* rather than incomplete. Never renumber; existing §8.1 references
   must still resolve.
6. **KCB now has four re-ratification counts** and they are independent: the media-transform
   extension re-run, the §7.5 live-schema-mutation re-run, the multi-authority pass for §3.1, and
   the firehose re-run for §4.2. Any future fold must restate all four and move only its own.
