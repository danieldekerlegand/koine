## Codebase Patterns
- **ADRs are the heavy artifact here.** The bar set by ADR-0011/ADR-0010 is: dated measurements
  (not assertions) → options considered with each one rejected *on a named ground* → a numbered
  Decision → a **checkable** re-open/withdrawal trigger + an explicit "what does NOT re-open it"
  list → an appendix recording the prior-art sweep as a table → a "Relationship to the specs"
  section. Match that shape; a short ADR reads as unfinished in this repo.
- **The one-sentence instrument:** ADR-0011's *"koine specifies what crosses an organizational
  boundary, not how one organization decides."* Almost any in-scope/out-of-scope question can be
  decided by applying it, and doing so explicitly is cheaper and more defensible than re-arguing.
- **`adopt-by-reference` is the default disposition.** Before minting anything, sweep for a
  standard; if the sweep is empty, *say so in a dated appendix* — the emptiness is part of the
  justification. `78-kft-adopt-by-reference` is the rule cited for this.
- **Fail-safe defaults have a house style:** an absent optional field reads as *unknown*, never as
  the benign value (KCB §4.2a `volume`). Reuse that phrasing.
- **Mirrors to keep in step when adding an ADR:** `decisions/README.md` table row **and** the
  `decisions/` bullet in `CLAUDE.md` ("keep this list and that table in step"). Neither is
  machine-checked for *content* — only links are.
- **Guards (all fast, run them all):** `node scripts/check-doc-integrity.mjs` (relative links +
  anchors + the 3 status tables), `check-schemas.mjs`, `check-registry.mjs`,
  `check-tasklist-categories.mjs`. `.chief/verify.sh` selects by changed path and reports
  "no changed files" until you commit — run the guards directly, not via verify.sh, mid-work.
- **Doc-integrity checks `#anchor` fragments too.** Prefer linking a file and naming the section in
  prose (`[`../specs/capability-bus.md`](...) **§4.2**`) — that is the house style and cannot rot.
  Verified-good anchor if you need one: `specs/README.md#the-ratification-gate`.
- **Relative-link depth trap:** files in `docs/reference/` reach ADRs as `../../decisions/...`.

## Iteration 1 — US-1 "Decide whether posture is a contract at all"

**What I did.** Wrote `decisions/ADR-0013-autonomy-posture-boundary-clause.md` (483 lines),
**Accepted (2026-08-26)**, answering the parked question **yes — in the boundary half only**, and
explicitly **rejecting the console's four-rung ladder** as the fabric vocabulary.

**The load-bearing findings** (both are grep-level facts about this repo, not opinions — reuse them):
1. A posture gates **spend and irreversibility**. Spend is fully expressed *and enforced across an
   ownership boundary* (KCB §5 grants, `budget_units` ceiling, projected cost before invoke, §4.2e
   metered subscriptions). **Irreversibility is expressed nowhere** — a sweep of all six specs finds
   no effect class / read-only / destructive / externally-visible marker on any capability or port;
   the only neighbours (`idempotent`) are about *redelivery*, i.e. the stream, not the world. So a
   cross-owner posture today is not *weak*, it is **inapplicable**. This is what made the answer
   "yes" rather than "no".
2. Only two things bind across an ownership line: the **callee's unilateral gates** (KGP §7, KCB §5,
   KFT §4/§8.1 — refusal always available) and the **credential the caller narrows**. Therefore the
   clause must be a narrowing of those, never a mode flag the callee is trusted to honour.

**The design the ADR authorizes** (this is US-2's brief — read it before starting US-2):
- One minted operand: a port **effect class** (absent ⇒ *unknown*, never *harmless*).
- A posture **operand** on existing verbs, in KCB §4.2's established operand shape.
- **Monotone-restrictive**: a posture never grants autonomy, only removes it ⇒ effective posture is
  the **intersection**, *the restriction always wins*, each side enforces its own half. That answers
  US-2's "which wins" with **no arbitration and no trust**, and is also what keeps ADR-0011's
  unilateral-gate premise intact so its trigger **T3 does not fire** (state this in the clause).
- **The floor:** no posture relaxes KGP §7 / KCB §5 / KFT §4 / §8.1; an unadmitted effect is a
  **refusal**, never a silent proceed *and never a silent substitution* (KFT §3.3's disposition);
  an undeclared class is not admitted.
- No new plane, verb, artifact kind, media type or authority role; MUST be expressible by an
  implementation with **no console at all** (a conformance requirement, per US-2's 4th criterion).

### Learnings for future iterations
- **The PRD description's "PARKED — do not start" is context, not a stop order.** The right move was
  to do the work *and* answer the prematurity objection inside the ADR rather than skip or hedge.
  The technique that made that defensible: keep the parking condition ("a **second** independent
  implementation") but move it from a gate on the *decision* to a gate on **ratification**, and show
  that nothing in the decision derives from the first implementation (the console's four rungs
  appear exactly once in the ADR — in the rejected option).
- **Two ADRs can reach opposite verdicts from the same premise, and the asymmetry must be stated.**
  ADR-0011 declined G2/G3/G4 because the concern never reached the wire; ADR-0013 accepts because it
  reaches the wire at two named edges *and* the needed operand is missing. I wrote that contrast out
  explicitly in option (a) — without it the two records look inconsistent.
- **Naming the concrete edges is the repo's method, and it survives the role-scoping rule.** Product
  names are fine in an ADR's *Context* when sourced to `ECOSYSTEM.md` §3 (informative); the
  **Decision** section stays role-scoped. ADR-0011 does the same.
- **Watch for a decision that would make a gate joint.** ADR-0011's trigger T3 fires if any koine
  gate stops being unilateral — so any new clause should be checked against it and should say so.
  The monotone-restrictive framing was chosen *specifically* to avoid firing T3.
- **Prior-art honesty beats fake precision.** Where I could not confirm an upstream detail against
  this repo's pinned revisions, the sweep row carries an explicit **verification item** and the
  Decision is written so **no verdict depends on it**. Do that rather than asserting a version.
- **GOV-2 (gates decide and record nothing) is the natural companion** to any escalation/posture
  work and keeps coming up. It stays open; do not fold it in sideways.

## Iteration 2 — US-2 "If it is a clause, it is role-scoped and product-agnostic"

**What I did.** Wrote the clause ADR-0013 authorized, and the pressure leg that shapes it.

1. `scenarios/kcb-cross-owner-posture.md` (new, 426 lines) — an **adversarial** leg against the
   ADR's own design, run at the two cross-owner edges of `ECOSYSTEM.md` §3. Eight deltas
   **AP-1…AP-8**, blocking **AP-5**. It is written against **KCB 0.4.7** (pre-clause), so the fold
   is earned rather than asserted — the repo's method (firehose → 0.4.7, resume → KFT 0.6.0).
2. `specs/capability-bus.md` → **0.4.8** (patch): normative **§4.3** (nine lettered clauses a–i),
   an `effect` paragraph in §2.1 beside `volume`/`cost`, a posture bullet in §5, verb-table
   pointers, status note, fifth re-ratification gate in *Pressure test*, changelog entry.

**The design, and why each piece is there** (read this before any follow-up touching §4.3):
- **`effect` = `reversibility` (none|local|irreversible) × `visibility` (internal|external)**, on a
  capability *or* a port, **outside** the `schema_id` digest exactly as `cost` and `volume` are.
  Absent ⇒ *unknown*, never *harmless*. `fetch` deliberately gets **no** class — KMI §7.1 already
  gates it fail-closed in the holder's own domain, and two gates over one act would disagree.
- **A posture is a SET of admitted classes**, not a rung. The sharpest argument found while writing:
  the two axes are independent, so two postures can each be stricter on a different axis —
  **no total order exists**, and any single ladder silently discards one of two ordinary rules.
  That is what makes "koine adopts no rung names" a *derivation* rather than a preference.
- **Monotone-restrictive intersection** answers "which wins" with *the restriction, always* — and
  needs no arbitration because no host is on the path (the **BP-5** fact, reused).
- **AP-5 is the finding that mattered.** A pairwise posture **evaporates at the second hop** while
  spend propagates (the grant carries it). Fix: a declared class covers the **leg**, not the
  callee's own code, and a re-dispatch may narrow but never widen — modelled on §5's chain rule.
- **AP-7** forced the clause to say *what a declaration is worth*: silence costs the declarant
  (fail-safe default), a misdeclaration breaches a **signed**, KCS-assertable term, and the grant
  binds where the posture is only read. Without that paragraph the clause reads as a security
  control it is not — which is exactly the advisory-hint defect it was written to avoid.

### Learnings for future iterations
- **Write the scenario against the PRE-fold spec, then fold.** Writing it against the folded text
  would make it a walkthrough, and this repo's gate is adversarial: the leg must be able to say
  *"and here is what the spec could not do."* It also produces the Findings table the changelog,
  the status note and the ROADMAP row all cite — those four documents are much easier to write when
  a numbered delta exists for each.
- **Let the leg beat the ADR.** ADR-0013 was thorough and still missed AP-5 (the delegated leg),
  because a decision record reasons about *a dispatch* and a scenario is forced to walk *a chain*.
  Budget for at least one blocking finding against your own authorizing record, and record in the
  ADR's amendment log which verdicts survived — a fold that reports "everything held" is a fold
  that did not attack.
- **A version bump's "patch, not minor" argument has a fixed template here** and it is worth
  copying verbatim: every field optional on read *and* write · a participant declaring nothing
  behaves exactly as at the prior version · no verb/plane/port kind/media type/authority role added
  · §7.2's table undisturbed so no live subscriber breaks · **0.5.0 is already spoken for** by
  §7.3's removal of §2.2's standalone manifest (and §7.3c forbids folding a removal into an
  unrelated publication). That last clause is what keeps KCB on patch bumps.
- **Reuse the push channel, never mint one.** §4.2d specifies *one* in-band control channel in both
  directions and binds any future V-7 fold to it. Anything needing a producer→subscriber signal
  (here: an effect-class change on a live binding) must ride it and say so.
- **New scenario ⇒ two mirrors and one cross-repo red light.** `scenarios/README.md` (row + the
  count in the amended note + the intro's "these N documents") and `ROADMAP.md`; and downstream
  `agora/console/src/kcs/scenarios/coverage.test.ts` asserts set-equality with `scenarios/*.md`, so
  the addition goes red there with no local guard to warn you. Say it in the row, the scenario and
  the ROADMAP — this leg is the **twelfth** against a downstream set of **nine**.
- **A ROADMAP row must not link a live tasklist JSON.** It moves to `tasks/chief/completed/` on
  retirement and the link rots; doc-integrity will then fail for a later, unrelated iteration.
  Reference it as plain `` `chief/NN-name` `` — the existing rows' convention.
- **When a measured grade changes, re-derive it, don't edit it.** `governance-taxonomy-map.md`'s G5
  moved only because clauses now exist; the note says so explicitly and keeps the *not Complete*
  reasons (intra-org half out of scope, GOV-2 still open). Grades in that file are measurements
  with dates, not opinions.
