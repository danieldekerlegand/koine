## Codebase Patterns

- **A "re-validation" lands as an appended section in the scenario, never as an edit to the
  original attempts.** Precedent: `scenarios/e2e-multi-authority.md` § *Re-run — Steps 1–10
  walked by hand against the folded text*. The original pass's Findings table stays as the
  record of what THAT pass found; a new delta gets a one-paragraph "not in the table above,
  deliberately" pointer under it (the MA-12 pattern) and is defined once in the new section.
- **Doc-integrity anchors: em-dashes collapse to a SINGLE hyphen.** `### Findings — from the
  re-validation` → `#findings-from-the-re-validation`, not `#findings--from-...`. Guessing the
  GitHub double-hyphen form fails the guard.
- **Retiring a tasklist deletes `tasks/chief/<n>.json` and breaks every markdown link to it.**
  That is how `main` was left red on doc-integrity here. Cite a tasklist as a plain code span
  (`` `chief/89` ``), never as a relative link — that is already the convention for every other
  retired tasklist in ROADMAP.md.
- **Run the gates the way the merge gate will:**
  `git diff --name-only HEAD | .chief/verify.sh --plan` to see the selection, then
  `.chief/verify.sh --run <files…>`. A bare `--plan` reads stdin and reports nothing under an
  agent shell.
