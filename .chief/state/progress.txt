## Learnings for future iterations

- **The single sharpest analytic move in this repo is: find a clause that states a normative
  consequence and then check whether ANY field, frame or table row carries it.** Four of this walk's
  six findings are that shape (V-10, BP-8, AP-9, ADR-0014's marking), and ADR-0014 had already named
  the axis in advance — *every operand kept outside the `schema_id` digest is outside the merge key
  too*. When walking a KCB fold, enumerate the operands outside the digest (`cost`, `volume`,
  `effect`, `binding`, the deprecated marking) and check each against §7.2's table and §7.3g's frame
  table. `cost` and `binding` have rows; `volume` and `effect` do not.
- **A fold's own MAY/MUST asymmetry is where a folded delta comes back.** V-11 and BP-7 are both
  "the section states the discipline correctly one paragraph away and does not extend it": §7.1 step 5
  has a MUST NOT on the branch that doesn't need the rule id and no MUST on the branch that does;
  §4.2c says *silence is not one of them* for `resume` and §4.2b/d say nothing for a live adjustment.
  Read a folded section for which branch got the MUST.
- **Check the published flip/regression step lists before walking them.** `e2e-live-schema-mutation`'s
  *Fold status* corrected Step 3's mis-filing and made the identical error for Step 6 in the same
  breath. A count's step list is prose and is not guarded.
- **`.chief/verify.sh` with no args reports "no changed files" under an agent shell** (its `--plan`
  reads STDIN only when stdin is not a tty, which it never is here). Run it as
  `git diff --name-only main | .chief/verify.sh --run` — or pass the list with `xargs`.
- The five guards are: check-doc-integrity, check-doc-links (`--ratchet --base main`),
  check-tasklist-categories, check-schemas, check-registry. `verify.sh` selects them from changed
  paths and `verify-test.sh` asserts that mapping — the selftest runs as one of the gates.
- **CLAUDE.md's *Current state* prose is the unchecked fourth mirror.** doc-integrity checks three
  status tables against the spec headers and never this. Update it by hand every time.
- Insert new sections with a python `str.index('## Downstream results')` splice — every scenario keeps
  *Downstream results* last, so that marker is a stable insertion point ahead of it.

## Learnings for future iterations

- **When a dependency tasklist already executed your story's literal instruction, the value is in what
  changed since — not in re-performing it.** The honest move was to state that `chief/89` did the
  first pass, then find the one thing that made a second pass non-redundant (US-1's findings landing
  on a shared axis). Restating a dependency's verdict as your own would have passed the acceptance
  criterion and taught the record nothing.
- **The axis generalizes across planes, and koine's own ADR says so without anyone having applied it.**
  ADR-0014 generalized *every operand kept outside the digest is outside the merge key too* for KCB.
  The same sentence read over KMI gives MA-13 immediately. When walking any spec, list the fields
  **excluded from that spec's content hash** and ask, for each: who asserts it, can two asserters
  disagree, and does any clause rank them? (`license`/`egress` on the `asset` id; `cost`/`volume`/
  `effect`/`binding`/the deprecated marking on `schema_id`.)
- **A MUST written over one object whose operand only exists on another object is a delta.** §7.1(e)
  bullet 2 says *an asset's egress*; every operand a holder can obtain is a property of *an envelope*.
  Same shape as V-10 (a MUST routed to a frame table with no such frame) and ADR-0014's marking.
- **Check whether a "declared residual" covers the case you found.** The first pass declared the
  *downgrade* (falsified pair) a residual answered by attribution. Divergence is not that case:
  nobody misdeclares, both prov chains are clean, and attribution says who said what when the
  question is which one governs. Naming the difference explicitly is what makes the finding stick.
- **Register-of-record files go stale in the direction of optimism.** `scenarios/README.md`'s
  federation paragraph still read *"that re-run has not happened"* after `chief/89` ran it; only the
  delta-range cell had been updated. When you touch a scenario, grep its filename across
  `scenarios/README.md`, `ROADMAP.md`, `docs/reference/promotability.md` and `CLAUDE.md` and read
  every prose hit, not just the table cells — **no guard checks prose.**

## Learnings for future iterations

- **A "write it down" story is where you re-check the claims you are about to write down.** Two of the
  six AG findings had moved since the 2026-08-25 read and nobody had looked; had this iteration copied
  the table forward, koine's record would have gone on saying *four versions stale, reason unwritten*
  about a register that now declares its lag properly. The generic form: **when a doc quotes another
  repo at a sha, re-take it at the current sha before repeating it.**
- **A closed finding can be more informative than an open one.** AG-5 looked like bookkeeping; the reason
  written into its fix says the reference implementation *cannot* advance to KCB 0.5.0 without making the
  exact change §7.2's fold asks of a reader. Read what a downstream fix says, not just that it happened.
- **`agora` is read-only from here (ADR-0001).** Reading source and *running* its gates is right;
  editing anything there is not, and the AG findings are deliberately reported in koine, never filed there.
  `bun test <path>` needs the path to contain `.test.` — `console/src/live/evidence.test.ts` is the
  evidence gate, not `console/src/kcs/…`.
- **The evidence artifact's per-scenario `gates` field is the thing that makes a green citable.** It names
  the spec section the encoding was written for. A green with the wrong `gates` value is DR-4's defect
  (`kcs:kmi-otio-roundtrip`); a green with the right one is still only a precondition.
- **When a re-derivation concludes "unchanged", publish the derivation anyway.** The page's own idiom is
  *"the ordering below is unchanged, and that is a claim worth checking rather than assuming"* — a table
  with a per-row *what would move this* column is more useful than a re-ordered list would have been, and
  it is what surfaced the KMI/KCB coupling.
