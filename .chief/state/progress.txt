## Codebase Patterns

- **koine has almost no code.** 140 tracked files: 65 json, 57 md, 7 tsv, 5 mjs, 2 sh.
  No `package.json`, no dependencies, no runtime (ADR-0001: "koine specifies, agora
  implements"). The entire executable surface is `scripts/check-*.mjs` (5 guards) plus
  `.chief/verify.sh` + `.chief/verify-test.sh`. A "dead code" sweep here is a sweep of
  seven files.
- **`.chief/verify.sh` is the one gate, and it is path-selective.** Run it as
  `.chief/verify.sh --run <changed paths...>` — a bare run diffs `main...HEAD`, so it
  reports "no changed files" on an uncommitted working tree. `--plan` prints the
  selected gates without running them. A path matching NO rule selects the **umbrella**
  (every gate, including the self-test).
- **`check-doc-integrity.mjs`'s slugify is NOT GitHub's** (line 65-73). Two ways it differs,
  each of which has cost a red gate: it collapses `\s+` to a SINGLE hyphen, so
  `## Class A — dead: removal candidates` anchors as `#class-a-dead-removal-candidates`, not
  GitHub's `#class-a--dead-removal-candidates`; and it **strips `_` along with backticks and
  `*`**, so `### A-1 — EXCEPT_DIRS, and …` anchors as `#a-1-exceptdirs-…`, not
  `#a-1-except_dirs-…`. Match the guard, not GitHub.
- **`MD_LINK` fires inside backticks.** Writing `` `[text](path)` `` in prose is parsed
  as a link and reported as "no such file — path". Split the form when writing about it.
- **`tasks/chief/completed/` is history and must not be rewritten** — both doc guards
  skip it as a citer, and reference counts that include it measure the past.
- **A deadness search must ask "is it used, OR ABOUT TO BE?"** Grep the ACTIVE tasklists
  (`tasks/chief/*.json`, excluding `completed/`) as part of every one. koine's tasklists
  schedule conventions before the tree has them, so an unreferenced-today path can be a
  requirement one tasklist away — that is how US-2 nearly deleted the `docs/archive/` skip
  that `901-docs-tell-the-truth` mandates. Re-run every search AT REMOVAL TIME, not only at
  inventory time.
- **A citation count is not evidence when the counter is inside the corpus.** A document that
  enumerates its findings by name becomes a citer of every one of them, so re-running the
  search that produced it returns 0. Exclude the document explicitly
  (`':!docs/reference/<the-doc>.md'`) and say so in the document. Measured on US-3's register:
  23 findings → naive replay 0, correct replay 23.
- **`git ls-files` only sees TRACKED files, so every count in a new document is off by one
  until `git add`.** `check-doc-integrity` reads the filesystem and `check-doc-links` reads
  `git ls-files`, which is why the two disagree by exactly the new files during a session and
  agree after staging. Verify every count AFTER staging.
- **An assertion about tooling behaviour is a search that was not run.** US-1 wrote
  "`.chief/state/` is gitignored so `git ls-files` never returns it"; both files are tracked
  (an ignore rule does not untrack) and `git check-ignore -v` prints nothing. Run the command.

  clean; A-3's did not survive it.

  `.replace(/`|\*|_/g, '')`). So `### A-1 — `EXCEPT_DIRS`, and …` anchors as
  `#a-1-exceptdirs-…`, NOT `#a-1-except_dirs-…`. Cost one red gate. Add this to the slugify

- **The `guard-doc-links` ratchet is a free before/after test of any change to that script.**

### Learnings for future iterations
