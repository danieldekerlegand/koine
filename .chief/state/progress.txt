## Codebase Patterns

- **Run the guards from the repo root, and use the runner's own seam.** `node scripts/check-doc-integrity.mjs`
  (wall: every relative link + all 3 status tables) and `node scripts/check-doc-links.mjs --ratchet --base main`
  (ratchet). To gate exactly what you changed *before committing*, use
  `bash .chief/verify.sh --run <paths...>` — a bare `.chief/verify.sh` reads the branch diff and
  reports "no changed files" for uncommitted work.
- **Anchor slugs are the guard's, not GitHub's.** `scripts/check-doc-integrity.mjs` `slugify()`:
  strip `` ` `` `*` `_`, unwrap `[text](url)` to `text`, lowercase, drop `[^\w\s-]` (so `/`, `—`,
  `,` vanish), trim, `\s+` → `-`. An em dash therefore collapses into a double space → single
  hyphen. Write the anchor by applying those five steps, not by guessing.
- **One home per fact.** Where a table already exists (the ADR table in `decisions/README.md`, the
  three spec status tables), link it — do not restate it. Restating is how the four version/status
  mirrors got expensive.

### Learnings for future iterations
- **`docs/README.md` is now the declared-exception document.** If a story moves a directory or adds
  one, that table is the thing to update — and `archive/`'s row says *"created on first use"*, so
  **US-3 must flip that row** when it archives its first document.
- **Do not restate the ADR table in `docs/README.md`.** It was tempting for reachability, and it is
  exactly the duplication US-2's third AC forbids. The row links `decisions/README.md` and says in
  writing that it is the one home. Keep it that way.
- **Left for US-2 (found while reading, not fixed here):** the root `README.md` "Repository layout"
  table lists 8 paths and **omits `scripts/`**, which is where the guards CLAUDE.md tells you to run
  actually live. That is content drift, not structure — it belongs to US-2.
- The guards are cheap and fast (~1s). Run them after every edit rather than at the end; a broken
  anchor is much easier to find one edit at a time.
